# アフィリエイト記事 品質・文字数基準（AFFILIATE_ARTICLE_STANDARDS）

作成: 2026-08-04（TASK-031）
位置づけ: note・WordPress（店主のAI時短メモ）・Brain商品ページで、AIが記事を執筆・QAする際に
共通で従う基準。既存の `sns-post-quality-check` Skill（SNS投稿向け）・
`quality-reviewer` / `compliance-qa-reviewer` エージェント（コンプラQA）・
`master-content-producer` エージェント（執筆）を**置き換えず、その上に載る追加レイヤー**として運用する。

## 0. このドキュメントが解決する問題

これまでnote記事は「7,000〜10,000字」という単一の目安（`RIO_801_NOTE_OPERATIONS_SOP.md` §1、
REPORT-009の1実例ベース）しか無く、記事の種類に関わらず同じ長さを目指していた。
本ドキュメントでは、**記事タイプ・検索意図に応じて目標文字数を変える**ことで、
「文字数を埋めるための水増し」を防ぎ、「情報が足りないまま短く終わる」ことも防ぐ。

**重要な前提**: このリポジトリには検索順位・競合記事文字数を自動取得する有料SEO API
（Ahrefs/SEMrush等）は契約されていない（2026-08-04時点）。そのため「検索上位10記事の
文字数中央値」は**自動取得できない**。競合分析が必要な場合は、執筆者（Claude Code /
`master-content-producer`）がWebSearch/WebFetchで手動確認し、確認できた場合のみ
参考値として使う。確認できない場合は §1 の記事タイプ別レンジをそのまま使う
（これは妥協ではなく、「取得できないデータを推測で埋めない」という本リポジトリの
一貫した原則— CLAUDE.mdの捏造禁止、`master-content-producer.md`の出典明記原則— に従う）。

## 1. 記事タイプ別・目標文字数レンジ

| 記事タイプ | 目標文字数 | 想定媒体 |
|---|---|---|
| 悩み解決・使い方記事 | 2,500〜4,500字 | note（無料部分）・WordPress |
| 商品単体レビュー | 4,000〜7,000字 | WordPress |
| 比較記事（A社とB社、または複数社比較） | 5,000〜8,000字 | WordPress |
| おすすめランキング・まとめ記事 | 6,000〜10,000字 | WordPress |
| 高額商品・SaaS・スクール紹介 | 7,000〜12,000字 | WordPress |
| 商標キーワード記事（特定サービス名で検索） | 3,000〜6,000字 | WordPress |
| 用語解説・補助記事 | 1,500〜3,500字 | note・WordPress |
| 購入方法・申込方法記事 | 2,000〜4,000字 | WordPress |
| Brain商品ページ（商品説明文） | 1,500〜3,000字 | Brain |
| note有料記事（無料部分＋有料部分の合計） | 7,000〜10,000字 | note（既存実績REPORT-009を踏襲、内訳は無料2,000〜2,500字＋有料残り） |

これは固定値ではなく初期レンジ。以下の場合はレンジ内で調整する。

- 商品数が多い比較記事（4社以上）→ レンジ上限寄り
- FAQが多い記事 → レンジ上限寄り
- 一次情報（実際の操作画面、独自整理）が少ない記事 → 無理に長くしない。検索意図を
  満たせるなら短くてよい
- 手動で競合記事を確認でき、明らかに競合が簡潔（例: 上位記事が軒並み2,000字未満）
  なのに記事タイプ的に6,000字目安になっている場合 → 検索意図を優先し、レンジ下限
  またはレンジを下回ってもよい（ただし記事タイプの下限文字数を大きく下回る場合は
  情報不足を疑い、内容を見直す）

**文字数を増やすこと自体を品質向上とみなさない。** 同じ内容を別表現で繰り返して
文字数を稼ぐことは §4 の品質基準違反として扱う。

## 2. 検索意図の分類

記事執筆前に、メインキーワードを以下のいずれかに分類する。

| 検索意図 | 記事での扱い |
|---|---|
| 情報収集 | 強引な購入誘導を避け、関連記事・比較記事への誘導にとどめる |
| 問題解決 | 手順・チェックリストを重視、CTAは記事後半に控えめに |
| 比較検討 | 比較表・選び方・違いを明示するのが必須要素 |
| 商品指名（特定サービス名で検索） | メリット・デメリット・料金・評判を整理 |
| 購入直前 | 申込み手順・キャンペーン条件・注意点を重視、CTAを複数箇所に |
| 申込み方法 | 手順の正確性を最優先、画面キャプチャ等の具体性が必須 |
| 解約・返金 | 正確性を最優先。無理な引き止め表現・誘導を書かない |
| 評判・口コミ | 実際に収集できた口コミ傾向のみ書く。存在しない口コミを創作しない |
| 代替商品探索 | 「〇〇の代わりになるもの」を軸に、比較と使い分けの提案を重視 |

## 3. 記事構成の必須要素（収益記事向け）

すべての記事に同じ見出しを機械的に入れるのではなく、記事タイプ・検索意図に応じて
必要なものだけ採用する。収益記事（アフィリエイトリンクを含む記事）では、以下から
該当するものを検討する。

1. 冒頭300字以内の結論
2. この記事で分かること
3. 商品・サービスの概要
4. 誰におすすめか
5. **誰にはおすすめしないか（必須。§4参照）**
6. メリット
7. **デメリット・注意点（必須。§4参照）**
8. 料金・費用
9. 他商品との比較
10. 口コミ・評判（収集できた場合のみ）
11. 選び方
12. 申込み方法
13. 解約・返金・契約条件（分かる範囲で）
14. よくある質問
15. 最終結論
16. CTA

---

## 4. 品質基準（禁止事項）

### 4.1 メリットだけの記事を禁止

デメリット・注意点・利用条件を必ず確認する。**デメリットが見つからない場合に、
推測で作らない。** 確認できないことは「確認できない」「公式サイトに記載がない」と
明示する。

### 4.2 公式ページの言い換えのみを禁止

販売元の説明を並べ替えただけの記事は不合格。以下の付加価値を最低1つ以上入れる。

- 複数商品の比較
- 料金比較
- 利用条件の整理
- 口コミ傾向の分析（収集できた場合のみ）
- 向いている人・向いていない人の分類
- 利用シーン別の判断
- 公開情報を横断した独自整理

### 4.3 虚偽の体験談を禁止

実際に使用していない商品について、使用したように書かない。禁止表現：
「実際に使ってみました」「私が契約した結果」「1か月利用して分かった」
「購入して検証しました」。

実体験がない場合は次のように明示する：「公開情報をもとに調査した」
「公式情報と利用者の口コミを比較した」「複数の公開情報から整理した」。

これは `RIO_801_NOTE_OPERATIONS_SOP.md` §1（REPORT-009の教訓：実体験プレースホルダー
未確定のまま公開しない）と同じ原則の全媒体版。

### 4.4 根拠のない断定を禁止

以下は禁止または要確認表現とする：「必ず稼げる」「絶対に効果がある」
「誰でも成功する」「最安」「業界No.1」「満足度No.1」「一番おすすめ」
「確実に痩せる」「治る」「改善する」。数値・ランキング・効果を書く場合は
根拠と出典を確認する（`master-content-producer.md` の既存原則を継承）。

## 5. 読みやすさの基準

- 冒頭300字以内で結論を示す
- 1段落は原則2〜4文
- スマートフォンで読みやすい分量に分割する
- 1見出しの本文は300〜800字を目安にする
- 長い説明は表・箇条書き・手順に分解する
- 結論を先に書く
- 同じ内容を別表現で繰り返さない
- 「この記事では〜」の連発を避ける

---

## 6. CTA設計

CTAは記事末だけに置かない。記事タイプに応じて以下から選ぶ。

- 冒頭の結論直後
- 商品概要の直後
- 比較表の直後
- メリット・デメリットの直後
- 料金説明の直後
- 最終結論の直後

CTAの連続配置・過剰な購入誘導は禁止。CTAには次を明示する：クリック後に何が
起きるか／公式サイトへ移動すること／申込みまたは詳細確認であること／
キャンペーン条件（ある場合、正確な期限）／アフィリエイトリンクである旨の表示
（景品表示法・ステマ規制対応、既存 `master-content-producer.md` のPR表記原則を継承）。

## 7. QAゲートとスコアリング（quality-reviewer / compliance-qa-reviewer 適用）

`quality-reviewer.md` の既存判定（PASS/FIX_REQUIRED/BLOCK）に加え、収益記事
（アフィリエイトリンクを含む記事）では以下のスコアリングを併用する。

| 評価項目 | 配点 |
|---|---:|
| 検索意図への適合 | 20点 |
| 情報の正確性 | 15点 |
| 独自性・付加価値（§4.2） | 15点 |
| 購入判断材料（メリット・デメリット・比較） | 15点 |
| 読みやすさ（§5） | 10点 |
| 比較・デメリットの充実度 | 10点 |
| CTAの適切さ（§6） | 5点 |
| コンプライアンス（§4.3, §4.4、既存BLOCK項目） | 10点 |

**公開条件**: 総合85点以上 かつ 検索意図15点以上 かつ 情報の正確性12点以上
かつ コンプライアンス8点以上 かつ 重大エラー（BLOCK相当）0件。

85点未満の場合は執筆担当（`master-content-producer` / Claude Code）へ差し戻し、
修正後に再監査する。**再監査は最大3回まで**。3回で基準未達の場合は自動修正を止め、
ゆうさんへ人間確認として申し送る（無限ループで文字数だけ増やし続けることを防ぐ）。

このスコアリングは既存の `sns-post-quality-check`（0-10点、SNS投稿専用）とは
**別枠**として運用する。SNS投稿（Threads等）は引き続き `sns-post-quality-check` のみを使う。

## 8. 記事ごとに記録するデータ

`note_posts_queue.csv` / `wordpress_posts_queue.csv` / `content.csv` の
該当カラム（各ファイルのコメント欄参照）に記録する。主な項目：

`keyword` / `search_intent` / `article_type` / `target_word_count_min` /
`target_word_count_max` / 実際の文字数（`free_char_count`+`paid_char_count`、
または `actual_word_count`） / `qa_score` / `compliance_score` / `human_approved`

有料SEOツール・自動計測（検索順位・CTR・成約率等）は本リポジトリでは未契約のため、
`metrics.csv` への手動記録（既存の48-72h後手動計測フロー）をそのまま踏襲する。
自動PDCAループの構築は、計測インフラ（SEOツール契約・Google Search Console連携等）
の整備が前提となるため、本ドキュメントの対象外とし、将来タスクの候補として
`design/AFFILIATE_ARTICLE_STANDARDS.md` §9 に申し送る。

## 10. 適用範囲・非対象

- 適用対象: note記事（無料部分）・WordPress記事・Brain商品説明文
- 非対象: Threads投稿（`sns-post-quality-check` のみを引き続き使用、文字数レンジも
  Threads用の既存ルールをそのまま使う）
- 完全自動公開は行わない。本ドキュメントの基準を満たしても、公開ボタンは
  引き続きゆうさん本人が押す（CLAUDE.md・RIO_801/RIO_802 SOP準拠）。
