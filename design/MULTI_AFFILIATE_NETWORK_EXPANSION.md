# マルチアフィリエイトネットワーク対応 拡張方針（設計のみ）

作成: 2026-08-03（TASK-024・CEOキックオフ Week1 フォローアップ）
関連: TASK-023（Monday キックオフ）でのゆうさんの質問
「楽天以外にA8.net・もしもアフィリエイトも使うか」への回答の具体化。

## 0. 結論（CEO方針の再確認・2026-08-03追記で更新）

A8.net・もしもアフィリエイトは口座・税務情報の登録を伴う新規アカウント開設が
必要で、これは**ゆうさん本人にしかできない**という前提で本ドキュメントは
当初作成された。同日中に、**ゆうさんが既に両ASPのアカウントを開設済み**
（A8.net: メディアID a24062165409・yuublog様／もしもアフィリエイト: 「店主のAI時短メモ」
スモールビジネスカテゴリ）であることが判明したため、想定していた最大の障壁は
既にクリアされていた。

これを受けて、`affiliate_link_library_v2.csv`（旧 `_proposed_schema.csv` から
本PRでリネーム）に、ゆうさんの実アカウントから実際に発行を確認した広告リンク
3件（A8.net 1件・もしもアフィリエイト 2件、いずれも「店舗オーナー向け
バックオフィス効率化＝会計・勤怠・労務」ジャンル）を投入した。ただし
DEV_RIO_705 等の自動投稿ワークフローへの組み込みは本PRの範囲外とし、
ゆうさんの承認を得てから別タスクで実施する（CLAUDE.md準拠）。

`products/revenue-intelligence-os/data/offers.csv` の `program` 列には
既に `off_01`（三井住友カード, A8.net）、`off_03`/`off_04`（freee/マネーフォワード,
もしもアフィリエイト / A8.net）など、A8.net・もしもアフィリエイトを前提とした
オファーが存在する。つまり**商品選定レベルでは両ASPの利用が既に織り込まれており、
今回のスキーマ拡張はそれを実行層（リンクライブラリ・投稿ワークフロー）に
追いつかせる作業**という位置づけになる。

## 1. 現状: rakuten_link_library.csv の構造

カラム: `id / genre / product_name / affiliate_url / pr_note / status / added_date`

- 単一ネットワーク（楽天）専用。`network` 列が無いため、将来複数ASPのリンクを
  同じ台帳に混在させると識別できない。
- `genre` はDEV_RIO_705が生成する `product_genre` と照合するためのキー。
  ネットワーク非依存の値（例: `photo_gear` はどのASPで契約しても同じジャンル）。
- 投稿文には genre一致時のみ固定文言「`#PR`」が付く運用（ステマ規制対応、
  2026-08-03時点の最新仕様。旧仕様の「【PR】」表記から変更済み）。

## 2. 拡張スキーマ案（v2・提案のみ）

新規ファイル `products/revenue-intelligence-os/data/affiliate_link_library_v2_proposed_schema.csv`
に提案スキーマを作成した。**本番の `rakuten_link_library.csv` は変更していない。**

### 2.1 カラム差分（v1 → v2）

| カラム | v1(楽天専用) | v2(提案) | 備考 |
|---|---|---|---|
| `id` | あり（`RKT-xxx`） | あり | v2では `RKT-xxx` / `A8-xxx` / `MOSHIMO-xxx` のprefixでネットワークを人間が見ても判別可能にする |
| `network` | **なし** | **新規追加**（`rakuten` / `a8` / `moshimo`） | マッチングロジック本体はこの列を見ない。表示・フィルタ・将来のレポート集計用 |
| `genre` | あり | あり（据え置き） | ワークフローの照合ロジックはこの列のみ参照し続ける＝**ネットワーク非依存を維持** |
| `aliases` | なし（RIO_700_SERIES_RUNBOOK.mdは「genre（またはaliases）」と記述しているが未実装） | **新規追加**（セミコロン区切り、例: `photo_gear;lighting;camera_accessory`） | ドキュメントと実装のズレを解消。genre一致に加えaliasesのいずれかに一致でもマッチ可とする |
| `product_name` | あり | あり（据え置き） | |
| `affiliate_url` | あり | あり（据え置き） | 手打ち・推測・生成URLの登録禁止ルールは継続 |
| `pr_note` | あり（運用メモ欄） | あり（据え置き） | 投稿文自体には固定文言「`#PR`」が付く仕様を継続 |
| `payout_type` | なし | **新規追加**（`cpa` / `rate` / `flat`） | offers.csv には既にこの概念があり、ネットワークによって報酬体系が異なるため（下記§3） |
| `network_account_status` | なし | **新規追加**（`active` / `pending_registration` / `not_registered`） | ゆうさんのASPアカウント開設状況を台帳側でも可視化。`not_registered` の行はワークフローが絶対に使わない（rakuten_link_library.csvの「捏造ゼロ」原則をnetwork単位にも拡張） |
| `status` | あり | あり（据え置き） | `active` / `inactive`。`network_account_status` とは別軸（アカウントはactiveでもリンク個別にinactiveにできる） |
| `added_date` | あり | あり（据え置き） | |

### 2.2 マッチングロジックの非依存設計

DEV_RIO_705（および将来の701）が行っている「Claudeが生成した `product_genre` と
ライブラリの `genre` を正規化して照合する」ロジックは、**`network` 列を一切
参照しない**まま拡張できる。具体的には:

1. Code ノードの `LINK_LIBRARY` 配列に `network` フィールドを追加するだけで、
   既存の照合関数（genre正規化・比較）は無改修で動く。
2. 同一 `genre`（または `aliases`）に複数ネットワークの候補がある場合
   （例: 同じ `marketing_book` ジャンルで楽天リンクとA8.netリンクの両方がある）、
   優先順位が必要になる。v2では単純な優先ルールを提案する:
   - `status=active` かつ `network_account_status=active` の候補のみを対象にする
   - 複数該当する場合は **配列内で先に登場した行を優先**（既存コードの
     `Array.find` 相当の挙動をそのまま使える。特別な優先度カラムを追加しない
     ことで実装をシンプルに保つ）
   - 将来、報酬額で最適化したくなった場合のみ `payout_type` を使った比較ロジックを
     追加検討する（現時点では実装しない＝過剰設計を避ける）
3. `genre一致時のみ #PR文言が付く` という安全設計（リンクなし投稿の防止＝
   `NO_LINK_SKIP`）は network が増えても変わらない。

### 2.3 CSVパーサの既知課題（TASK-023からの継続申し送り）

`posts_queue_v2_proposed_schema.csv` の設計メモで既に指摘済みだが、
DEV_RIO_705系のCode ノードは `line.split(',')` の単純分割でCSVを読む想定に
近い実装のため、`aliases`（セミコロン区切りだが将来カンマを含む可能性）や
`product_name`（既に商品名に「,」を含む行が実在。例: RKT-001の
`【楽天5冠達成!!】リングライト...`）でクォート処理が必要になる。
v2をn8n側に実装投入する前に、CSVパースをRFC4180準拠（またはこのファイルのように
JSON/配列をCode ノードへ直接転記する運用を維持）にする対応が必要。

## 3. A8.net / もしもアフィリエイト の特徴（判断材料・簡易調査）

以下はゆうさんが将来アカウント開設を判断するための一般的特徴の整理。
実際の審査基準・報酬額はASP側の最新規約を都度確認すること（本調査はWeb検索による
一般情報であり、確定した契約条件ではない）。

### 3.1 A8.net
- 国内最大級のASP。広告主数は2万社超と非常に多く、ジャンルの幅が広い
  （法人カード・SaaS・美容・金融など、`offers.csv` 記載の商材とも一致）。
- **登録自体はサイト審査なしで可能**（ブログ記事0本でも登録できる）。
  ただし個別広告主への提携申請時に、広告主ごとの審査がある場合がある。
- 登録に必要な情報: メールアドレス、**銀行口座情報（報酬振込用）**、
  運営するブログ/SNSのURL。
- 自己アフィリエイト（セルフバック）制度がある＝自分での購入でも報酬対象になる
  商材が存在（`offers.csv` のクレジットカード系オファーと相性が良い）。

### 3.2 もしもアフィリエイト
- 広告主数は2,600社超とA8.netより少ないが、物販・美容・金融・学習系など
  幅広くカバー。
- **楽天市場・Yahoo!ショッピングは審査なしで提携可能**（Amazonは審査あり、
  一定記事数が求められる場合がある）。楽天商材を「もしも経由」で扱う道もある
  （ただし既存の `rakuten_link_library.csv` は楽天アフィリエイト直接契約を
  前提にしているため、混在させる場合は `network` を `moshimo` として区別する）。
- 「W報酬制度」等、もしも独自の上乗せ報酬制度がある（詳細は登録時に要確認）。
- 楽天の高料率ショップ（例: 料率20%等）では、直接契約の楽天アフィリエイトの方が
  上限なく報酬を得られるのに対し、もしも経由は上限（例: 1,000円等）が
  設定されている場合がある＝**高額商材は直接契約、審査の緩さを取りたい商材は
  もしも経由、と使い分ける余地がある**。

### 3.3 比較の要点（ゆうさんの判断材料）

| 観点 | 楽天アフィリエイト（現行） | A8.net | もしもアフィリエイト |
|---|---|---|---|
| 審査 | 楽天会員なら比較的容易 | サイト審査なし・広告主別審査あり | 楽天/Yahoo!は審査なし、Amazon等は審査あり |
| 口座登録 | 必要 | 必要 | 必要 |
| 得意ジャンル | 楽天市場の物販全般 | 法人カード・SaaS・美容など横断的に幅広い | 物販・金融・学習など横断的、楽天/Amazon経由に強み |
| 高額商材の報酬上限 | 上限なし（高料率ショップで有利） | 商材次第 | 楽天経由は上限ありの場合あり |
| 既存offers.csvとの整合 | 既存rakuten_link_libraryのみ対応 | off_01/03/04等で既に前提とされている | off_03/04等で既に前提とされている |

### 3.4 いつ着手するのが妥当か（提案）
- Week1-4は¥0追加現金支出方針（TASK-023 CEO決定5）と整合させ、
  **無料で開設できる範囲**（A8.net・もしもアフィリエイトはいずれも登録自体は
  無料）であれば口座情報登録のタイミングはゆうさんの都合に合わせてよい。
- 開設の優先度は「今すぐ楽天だけで回らなくなった商材が出たとき」でよい。
  現状 `rakuten_link_library.csv` はまだ4件・Threads運用も検証段階のため、
  **緊急性は低い**。ただし `offers.csv` に既にA8/もしも前提の高スコア商材
  （off_01スコア58等）があるため、Threads運用が軌道に乗った後の
  「次に伸ばす商材」候補としては早めに検討余地がある。

5. 手動テスト実行で、複数ネットワークの候補から正しくマッチすることを確認。
