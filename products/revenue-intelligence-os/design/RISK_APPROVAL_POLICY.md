# RISK_APPROVAL_POLICY — リスク別承認（§17・§18）

承認負荷を増やしすぎず、リスクに応じて段階化する。

## リスク区分
| 区分 | 例 | 承認方式 |
|---|---|---|
| 低 | データ取得・下書き作成・分析・重複確認・QA・レポート | 自動実行候補（記録は残す） |
| 中 | 通常SNS投稿・無料記事・既存商品の紹介 | 一括承認候補（まとめてYes/No） |
| 高 | 有料note・Affiliate link掲載・PR投稿・強い販売表現・価格変更 | 個別承認 |
| 最高 | 課金・契約・金融/税務・Credential・権限変更・削除・本番デプロイ | **必ず個別確認** |

## 人間操作が必要な場面（§17）
n8nログイン / note・Threads・Googleログイン / OAuth / 2段階認証 / CAPTCHA / APIキーのCredential登録 / 有料契約 / 本番Activate / 公開・送信の最終承認

## 依頼様式（テンプレ）
```
【人間操作が必要です】
サービス：
現在の画面：
目的：
押す場所：
入力する内容：
注意事項：
完了後の返信：「完了」
```
- パスワード・APIキー・認証コードを Claude Code に貼らせない。

## 現行プロジェクトの適用
- Brain¥3,980（有料）への導線・PR表記・アフィリ掲載 = **高リスク（個別承認）**
- n8n Cloud のアップグレード（課金）・Credential登録 = **最高リスク（個別確認）**
- note/Threads 下書き作成 = 低〜中（下書き止め、公開は個別Yes）
