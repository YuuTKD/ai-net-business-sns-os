# BROWSER_USE_POLICY — 画面操作の規約（§16・§3）

## 基本
- Browser Use は**作業員**。事業判断はしない。
- 実行方法の優先順位（§4）: 公式API > n8n公式ノード > Webhook > CSV/インポート > **Browser Use画面操作**。Browser Use単独依存は不可。

## 許可される操作（read/draft）
- n8n を開く / Project・Workflow作成 / **JSONインポート** / ノード設定確認 / Credential選択 / 単体・全体dry-runテスト / 実行履歴確認 / エラー画面読取 / JSONエクスポート
- note へ下書き入力 / SNS投稿画面の操作（**公開直前で停止**） / 公開後の表示確認
- note編集画面で押してよいのは **「下書き保存」のみ**。それ以外の画面遷移・確認ボタンには触れない（下記インシデント参照）。

## 禁止（§3・§17で人間へ）
- 公開・送信・削除・課金・契約・Credential作成/変更/削除
- **note編集画面の「公開に進む」ボタン、およびそれ以降に現れる一切のボタン（設定画面・タグ入力欄・「投稿する」ボタン等）に触れない。** 「公開に進む」は名称に反し、記事の種類によっては**中間確認なく即座に本公開を実行する**ことが実測で確認されている（2026-07-31 インシデント）。「下書き保存」ボタンを押した時点で作業終了とし、それ以降の画面遷移は必ず人間が行う。
- CAPTCHA/2段階認証の回避 / 自動クリック・自己クリック・水増し
- ログイン・OAuth・2FA は**停止して人間へ依頼**（[[RISK_APPROVAL_POLICY]] 様式）

## ⚠️ インシデント実績（2026-07-31・重要）
「この画面から公開ボタンを押すまでの設定はあなたがやって」という指示のもと、note編集画面の「公開に進む」ボタン（設定画面への遷移ボタンだと想定）をクリックしたところ、**中間確認なく記事が即座に本公開された**（弥生アフィリエイトリンクを含む記事が一般公開状態に）。ゆうさんが即座に下書きへ戻し、実害は最小限に留まったが、「公開に進む」ボタンの実際の挙動を誤認した重大な判断ミスであった。
**教訓**: note.comの「公開に進む」ボタンは記事タイプ（無料/有料・スケジュール設定の有無等）によって中間確認ステップの有無が変わる可能性があり、事前に安全側を保証できない。したがって**「公開に進む」以降のボタンには一切触れないことを絶対ルールとする**（上記「禁止」欄に反映済み）。

## 再試行
- 同一画面操作の再試行は**最大2回**。2回失敗で停止し、失敗画面/ノード/操作/エラー/原因候補/人間操作要否/再開手順を報告。

## ダイアログ注意
- alert/confirm/prompt を誘発しない（拡張が固まるため）。必要時は console.log + ログ読取で代替。
